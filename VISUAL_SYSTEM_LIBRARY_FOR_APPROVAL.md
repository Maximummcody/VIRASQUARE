# ViraSquare Visual-System Library for Approval

## Purpose and design principle

ViraSquare should not use one repeated card shell for every carousel, and it should not use random visual changes per slide. The proposed library contains **eight coherent visual systems**. ViraSquare chooses **one system per content set** according to the content’s real job, then uses coordinated cover, body, example, checklist, and closing layouts inside that same system.

> **The visual system follows the content job. It does not decorate a generic card after the fact.**

Every system keeps the owner’s logo, business name, and optional Instagram identity visible in the established hierarchy. Text must still pass the existing fit safeguards, and factual product education must use only saved product and business information.

## System selection rules

| Rule | Decision |
|---|---|
| Primary selector | Content structure and job: guide, sequence, checklist, comparison, styling, misconception, question, or product education. |
| Secondary selector | The user’s business category and the saved brand colours determine the visual tone, not the system itself. |
| Carousel coherence | One post receives one visual system. Slides change by role inside that system, never by unrelated template. |
| Repeat control | The same system should not be selected for a nearby post from the same business when another eligible system fits equally well. |
| Safety control | Comparisons appear only for genuine contrasts. Product education uses only verified facts. No system can invent proof, ingredients, results, fit, price, or availability. |
| Text-fit control | Existing card-fit rules remain in force. If copy does not fit a role, ViraSquare changes the card break or uses a better-fitting role rather than shrinking text until it is weak. |

| System | Best content job | Typography | Colour usage | Layout rules | Graphic language |
|---|---|---|---|---|---|
| **1. | **2. ## Cross-system typography rules

The display font is reserved for a clear human takeaway, usually the headline or key phrase. It should not be used for long explanation paragraphs. The reading font is the current legible sans-serif, with a comfortable line length and no squeezed copy. Small uppercase labels should describe a role, such as **STEP 2**, **CHECK THIS**, or **YOUR QUESTION**, rather than carry essential information.

Every carousel has a hierarchy of **headline**, **supporting explanation**, **one actionable detail**, and **identity/footer**. A slide should not introduce a second competing headline. Body slides must contain a meaningful complete point, not a few decorative words.

## Cross-system colour rules

Brand primary colour remains the anchor. The selected system may introduce a carefully limited neutral or category-aware tonal surface, but it cannot replace brand identity with an unrelated palette. One carousel uses one dark anchor, one light canvas, and no more than two accent roles. Contrast must remain readable in all states.

The system can adjust the visual mood by content job: Lookbook Notes can feel more expressive, Field Checklist more practical, and Product Anatomy more factual. It must not use colour to imply performance, approval, urgency, or results the owner has not confirmed.

## System role arrangements

| Slide role | How systems vary without losing coherence |
|---|---|
| Cover | Uses the system’s strongest signature: editorial masthead, step outcome, question, contrast, or product topic. |
| Explanation | Prioritises readable body content and one useful supporting cue. |
| Example or application | Uses the system’s specific structure: a sequence action, checklist rows, comparison fields, style tags, or factual product detail. |
| Recap | Compresses the practical takeaway into one memorable action or prompt. |
| Closing | Preserves existing identity and CTA rules while adopting the system’s graphic language. |

## Proposed initial system mapping

| Content signal | First-choice system | Eligible alternative |
|---|---|---|
| “How to”, practical explanation, useful principle | Editorial Guide | Action Path |
| Sequence, routine, method, “three steps” | Action Path | Field Checklist |
| Things to check, buying guide, audit, red flags | Field Checklist | Truth Check |
| Genuine two-way comparison | Balanced Contrast | Editorial Guide |
| Outfit, styling, fashion pairing, beauty mood | Lookbook Notes | Editorial Guide |
| Common mistake, myth, assumption, correction | Truth Check | Field Checklist |
| Ask your audience, invite opinions, choices | Question Studio | Lookbook Notes |
| Product care, choosing, use case, feature education | Product Anatomy | Editorial Guide |

## Implementation boundary

This package does **not** approve automatic random template selection, new AI scene generation, invented product facts, or a visual change per individual slide. Implementation would expand the deterministic Card Engine only after the owner approves the systems and the two static examples.
